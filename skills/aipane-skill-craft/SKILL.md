# Agent Skill 编写与重构契约

Skill 是跨会话交付给强模型的「交接便签与验收契约」，不是替执行者把路走完的「文字版代码」。

## 1. 内容三分法（判断权归属）

动笔前先将待写内容归入三类，按不同权重处理：

| 类别 | 定义与例子 | 写法要求 |
| --- | --- | --- |
| **A. 推不出来的事实与硬边界** | 环境私有拓扑、账号/目录约定、踩坑得出的接口限制、用户认知偏好、不可逆/越权红线 | **写实、写死**。事实带验证日期或可重跑的核验动作；红线只花在“错了收不回”的操作上 |
| **B. 声明式完成态契约** | 输入签名、输出结构、怎样算完成的验收判据 | **写清“要什么”**。用可检验、穷尽的正面标准定义终点，拉动模型自主完成中间挖掘 |
| **C. 现场推理与探索路径** | 先查哪后查哪、通用分析步骤、单次成功排查的复盘顺序 | **默认不写**。模型现场生成路径几乎免费；把单次成功经验写成必经 SOP 会造成过拟合与能力封顶 |

## 2. 结构与注意力杠杆

1. **调用方式与双负载权衡（上下文负载 vs. 认知负载）**
   - **模型自触发（默认）**：保留 `description`，常驻每轮上下文。适合高频自然语言意图或被其他 skill 协同调用的场景。`description` 作为顶层指针：前置高区分度触发词，每个真实分支只留一个触发词，不重复正文已有的定义。
   - **仅人工点名触发**：设置 `disable-model-invocation: true`（属 Claude Code 等兼容宿主扩展字段，非所有宿主原生支持），零常驻上下文开销。适合会触发高耗时/外部调用、或用户明确只愿手动点名执行的专用工具；高频靠自然语言唤起的思维透镜可按调用习惯保留自触发，不必一刀切。
2. **按分支做渐进式披露（Progressive Disclosure）**
   - `SKILL.md` 主文件只放所有执行分支共用的事实、边界与核心契约。
   - 仅特定分支或弱模型才需要的长文档、API 样例、枚举字典，下沉到 `references/` 并用清晰的触发条件指针引用。
   - 同一概念的定义、条件与例外聚拢在同一小节（Co-location），保持单一事实来源（Single Source of Truth）。
3. **确定性进脚本，不进散文**
   - 必须每次一模一样执行的机械动作，写成 `scripts/` 下的可执行代码并在正文中给出调用签名；不要用自然语言写游标循环式的伪代码。
4. **预训练锚点词与正向约束**
   - 优先使用预训练语料中已凝聚强先验的专业概念词（如“幂等”“第一性原理”“BCNF”“原子发布”），避免自造口号式生词。
   - 用正面高标准替代大段“不要做 X”的负向禁令（防止把禁止项拉入注意力中心）；仅不可逆红线保留显式禁止。

## 3. 交付前五项检验（Pruning & Consistency）

对草稿逐段执行以下检验，不通过则整句删除、修正或下沉：

1. **重推导成本测试**：环境自己能回答的（`--help`、配置文件、目录结构、schema）或强模型默认就会的，直接删掉。
2. **No-op 测试**：删掉这句话后，当前模型在该任务上的默认行为是否会发生可观测的变化？不会则整句删掉。
3. **过拟合测试**：这条规则是不是把“上一次对话刚奏效的特解路径”当成了所有未来情境的必经关卡？若是，将其退化为完成态标准或可选样例。
4. **焦虑测试**：每个强制词（必须/严禁）能否回答“违反时用户的真实损失是什么”？答不上来的降级为背景信息。
5. **契约与实现一致性测试**：若技能附带 `scripts/`、`references/` 或引用其他技能，核验正文宣称的边界、参数、隔离级别与调用方式是否与脚本实现及被引用技能完全一致（例如不得在自触发技能中暗示自动调用 `disable-model-invocation: true` 的技能）。
