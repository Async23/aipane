# 语义残留审计契约

只有当被替代的旧概念不再拥有任何**行为权威（behavioral authority）**时，一次语义迁移才算完成。**语义残留（Residue）**指任何仍与新不变量矛盾、重复表达旧结果、对外暴露旧契约或隐式依赖旧概念的产物。必要的技术内部状态或有意保留的外部兼容边界，不会仅因取值超过两个就变成残留。

**默认执行只读审计**：仅在用户明确要求一并清理时，才进入清理分支修改文件。

## 1. 界定新不变量与审计覆盖面

- **精确新不变量**：从仓库规范、领域术语表、ADR、原始需求/Issue、近期对话与基线 diff 中提炼新不变量，使其精确到足以对任意代码行、字段、分支或报文判定“兼容”或“矛盾”。缺失项优先由仓库证据推断；仅当不同答案会实质改变“什么算残留”时，向用户提一个聚焦问题。
- **超越 diff 的覆盖标准**：绝不把审计范围局限在 diff 内。须同时从旧、新两侧沿数据链路追查全部生产者、消费者、控制流（含兜底与特性开关）、公共接口/DTO/Schema/持久化映射、测试（含 fixture/mock/快照）、监控告警/配置默认值与文档。
- **无旧词不等于干净**：被重命名的残留与重复状态轴往往不再出现旧词，须按行为与数据结构核验，而非只看关键词命中。命中自动生成文件或 vendor 副本时，追查其唯一源头，清理指向生成器或权威源文件。

## 2. 互斥分类与五项检验

将每条相关命中归入以下四个互斥类别之一：

- **确认残留（`CONFIRMED_RESIDUE`）**：与新不变量冲突、保留已废弃行为、重复维护单一事实来源或对外泄漏旧契约。
- **合法兼容层（`COMPATIBILITY_ARTIFACT`）**：为明确外部调用方有意保留的兼容契约，须写清调用方与退场条件；缺乏该证据时归入“待裁决”。
- **合法技术状态（`LEGITIMATE_STATE`）**：表达当前输入事实、过程状态、传输错误或审计明细，而非被淘汰的旧业务结果（不因追求表面简洁而强行压缩合法多值状态）。
- **待裁决（`UNRESOLVED`）**：现有证据不足以判定删除或保留。

对每条命中依次通过五项检验：**权威性**（旧概念是否为唯一存在理由）、**矛盾性**（能否产出新不变量禁止的行为）、**重复轴**（同一结果是否被两处字段/状态重复表达导致漂移）、**暴露面**（能否跨公共接口、持久化、事件、日志或界面泄漏）、**删除测试**（删后消失的是必要能力还是过时复杂度）。

## 3. 审计报告交付契约

- 开篇直接给出结论：审计范围内存在确认残留，或未发现确认残留（仅在覆盖面核查与分类检验全部满足后，才允许下“无残留”结论）。
- 每条“确认残留”与“待裁决”须给出：精确文件路径与行号、隐含的旧假设、与新不变量的冲突原因、影响层面（行为/契约/持久化/测试/运维/文档）及**最小根因级清理方案**（而非换名掩盖）。
- 报告按五节独立呈现：**确认残留**、**有意保留的兼容层**、**应保留的合法技术状态**、**待裁决项与所需证据**、**搜索与核验范围**。顺带发现但不属于语义残留的重要缺陷单列“邻近发现”，不稀释主报告。

## 4. 清理分支（仅用户明确要求时执行）

- 先移除过时的单一事实来源，使旧行为在类型或路径上不可表达、不可达，禁止换个标签保留旧轴；同步更新受影响的生产者、消费者、契约、测试、配置与文档，并用测试锁定新不变量。
- 保留的兼容层须将调用方与退场条件落成文档。完成修改并跑通对应测试后，**重新执行残留检索与分类，直至审计范围内零确认残留**；是否提交遵循所在仓库策略。
